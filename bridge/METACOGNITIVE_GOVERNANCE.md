# Metacognitive governance and external gates — Bridge candidate 0.3

**Release state:** staged, uncertified and not installed as a permanent service. Current service integration is a same-UID AF_UNIX local path; GitHub runner supplies separate asynchronous remote action/evidence. Neither is a public remote screen stream or unlimited sudo.

## Completed source interfaces
- metacog_diagnosis.py reads the exact admitted owner objective, separate unverified LLM proposal, current versioned time policy, evidence chain, current host resource readings and verified live-channel state. It executes three bounded evidence/authority/resource passes and emits the *next registered safe route*, never custom root commands. No fabricated model intelligence or provider Pro thinking control.
- live_link.py has same-UID local RPC for diagnose, report, bounded telemetry, safe scheduler ticks, structural LLM review and independently signed external gate preflight. Review requests are compared with the original admitted user objective. A signed gate must also bind the immutable mission SHA, declared user-objective SHA, specific requested capability, actual running transport source SHA, host and boot ID. A valid signature alone does not execute a task.
- external_gates.py checks owner/G23/G24 and distinct second-order G23_2/G24_2 signatures from an OUT-OF-REPO, root-owned, group/world-nonwritable local trust directory, with pinned public-key hashes. It rejects reused signing keys or issuer IDs, stale or changed machine/boot/source/mission, forged dependencies and missing second-order chain. It NEVER generates certificates or key material. Test keys are disposable fixtures, not real G23/G24 authorities.
- apc_inventory.py only re-verifies previously recorded Privilege Bridge 1.2.1 identities on the live host and uses narrowly fixed-path sudo sha256sum reads. No sudoers modification and no inferred authorization for this new Bridge.

## Authority boundaries
All root operations, sudo bash, changing partitions/fstab/boot and external remote ingress remain disabled in these modules. Gate preflight reports cryptographic validity and hashes but always returns execution_authorized_by_this_verifier=false. Actual issuer/operator independence, owner consent, single-use receipt consumption, runtime source manifest, and separate current code-specific signed G23/G24/G23_2/G24_2 must be proven by external actors. A historic Privilege Bridge PASS must NOT automatically pass this Bridge. The implementation cannot override ChatGPT platform controls or grant itself any permission.
