# LOUKSNA Remote Bridge — Elastic Metacognitive Automation v0.2

STATUS: ADDITIVE_SOURCE_CANDIDATE_UNCERTIFIED. No privileged or visual deployment. No new PART4 or PART5–9 execution authority.

## Owner objective, LLM accountability, elastic execution
The user objective and the model proposal are separate fields. An LLM declares its own name and version, which are never misrepresented as provider-attested. Model convenience cannot change the objective, Louksna.md authority, fresh approval requirements or external security controls. An unavailable capability becomes a recorded engineering dependency, not an invented PASS or a permission bypass.

Elastic means fulfilling the exact authorized task by changing legitimate routes under real host resource budgets. This module implements a deliberately narrow, repeatable **read-only** first stage, not a general autonomous AI or ChatGPT product-mode override.

## Operational code delivered
- Up to 32 persistent missions; 1–8 registered steps each; exact user objective, distinct model proposal, UTC deadline, bounded autonomous-step count, mission-input SHA-256, versioned time policy.
- One read-only step per run, followed by an atomic state checkpoint and chained evidence. Normal retries are idempotent.
- Registered steps: OBSERVE_LOCAL; INDEX_PRIORITY (explicit existing local root, up to 100 immediate entries, nonrecursive); GATED_OPERATION (proposal only: WAITING_FRESH_G23_G24, never executed).
- Resource prechecks: memory available at least 15%, root free at least 64 MiB, and bounded system-load estimate. Unknown metrics cause HOLD, not optimistic continuation. These prechecks do NOT claim cgroup-level guarantees.
- Rejection tests for forged step/sudo fields, scope reuse, stale evidence, mission tampering, low resources, missing model version, expired deadline, incomplete transaction and unauthorized credential/privilege assumptions.
- Distinct user/model fields enable an external CUSTOSZ V7 critic; the code does not pretend to be a model or an independent certifier.

## Local commands after source review
The authorized operator supplies a mission JSON with mission_id, user_objective, model_proposal, model.declared_name, model.declared_version, deadline_utc, max_auto_steps and registered steps. The three explicit verbs are:
  python3 -B bridge/elastic_automation.py --state-dir /authorized/private/state admit --mission-file /exact/mission.json
  python3 -B bridge/elastic_automation.py --state-dir /authorized/private/state run-once --mission-id exact-id
  python3 -B bridge/elastic_automation.py --state-dir /authorized/private/state report --mission-id exact-id
All verbs are local, unprivileged and operate on an explicitly supplied private state dir.
