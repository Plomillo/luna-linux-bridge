6. ROOT CAUSE

CONFIRMED HARNESS-LEVEL DEFECT:

The deterministic fixture preparation changes the active analysis input from setSeed=false to setSeed=true, seed=1, but deliberately preserves all non-active archive members, including the previously saved JASP result/reference material. The same clone is then passed to JASP with --unitTest. That mode compares the newly computed seeded analysis with the historical saved output still contained in the clone.

The test therefore compares results produced under two different RNG configurations:
- stored reference: generated when the active configuration had setSeed=false;
- current calculation: generated after the disposable test copy changes the active configuration to setSeed=true, seed=1.

The logs prove that this comparison is the direct trigger for the exit code 1. The same mismatch is reproduced in the flatpak_launch test and both round-trip invocations. The deterministic seed receipt validates the input-copy operation; it does not make the historic saved output equivalent to a newly seeded result.

The two GUI/runtime warnings seen in the logs (missing system D-Bus socket and transient GPU command-buffer errors) are not the primary failure: JASP initializes, runs the analysis, emits the model-comparison tables, and fails specifically when comparing those tables.

BOUNDARY OF CONCLUSION:
This evidence proves the test harness pairs a newly seeded input with old stored output. It does not, by itself, establish whether JASP 0.98.8 also has a computational regression relative to the application version that produced the archived reference output. That possibility must not be silently dismissed or silently accepted.
